# Troubleshooting

Проблемы, реально встреченные при настройке этой конфигурации, и что помогло.

## MCP

### Сервер `pending` сразу после добавления

Нормально: каталог инструментов подтягивается через несколько секунд. Проверьте ещё раз:

```sh
opencode mcp list
```

Если висит дольше минуты — смотрите лог `~/.local/share/opencode/log/opencode.log`, ищите `role=server` и имя сервера.

### `opencode mcp list` вернул пусто

Наблюдалось при параллельном запуске команды из скрипта. Повторите вызов — состояние сервера при этом не теряется.

### `needs authentication`

Remote-серверы используют OAuth. В TUI: `/mcps` → выбрать сервер → войти. Сбросить: `opencode mcp logout <name>`.

### Локальный сервер не стартует

- `command` должен указывать на существующий бинарник: для `browse` — абсолютный путь `~/.local/bin/browse`.
- `uvx`-серверы (`word`, `excel`) падают, если не установлен `uv`: <https://docs.astral.sh/uv/>.
- `npx`-серверы при первом запуске качают пакет — нужен интернет и место в `~/.npm`.

### Инструменты не видны в контексте

По умолчанию MCP-инструменты доступны через `execute` (Code Mode). Прямой список — `"codemode": false` у сервера; это раздувает контекст, но упрощает вызовы.

## browse

### `goto` зависает, хотя `browse status` показывает `connected`

Первая навигация иногда подвисает. Повторите вызов; если не помогает:

```sh
browse status
```

Проверьте, что Chrome запущен и расширение активно.

### Агент потерял вкладку

Закрытие отладочной панели Chrome (`Cancel/OK`) отключает browse от всех вкладок. Откройте вкладку заново кнопкой browse в тулбаре — агент снова её увидит.

### Предупреждение о версии расширения

```text
Warning: extension 0.0.16 differs from this CLI's 0.0.17
```

Протокол совместим (v3), работать можно. Если появится `protocol incompatible` — обновите расширение в Chrome Web Store.

### После перезагрузки нет соединения

Relay поднимается по требованию при первом вызове MCP. Нужен запущенный Chrome с расширением.

## Поиск

### Сайт отдаёт 503 (например, news.ycombinator.com)

Не ошибка конфигурации. Повторная загрузка обычно даёт `200`:

```js
await page.reload({ waitUntil: 'domcontentloaded' });
```

### `429` от провайдера поиска

Встроенный `websearch` падает, если провайдер один. Варианты:

```jsonc
{ "websearch": { "provider": "random" } }
```

или подключите второй провайдер через `/connect`.

### Parallel отдаёт странные URL

Бесплатный тир бывает шумным (порт в хосте, устаревший кэш). Авторизуйтесь: `parallel-cli login`, `/mcps` → `parallel`, либо используйте `parallel-web-search` через CLI.

## Навыки

### Навык не появился

1. Каталог должен содержать ровно `SKILL.md` (не `skill.md`).
2. ID = имя каталога, регистр важен.
3. Нужен `description` во frontmatter.
4. Проверьте `metadata.opencode/autoinvoke: false`.
5. Одноимённый навык из источника выше по приоритету перекрывает ваш.

### `PromptScript does not support global skill installation`

Предупреждение установщика `npx skills` про сторонний агент. Для OpenCode копия в `~/.agents/skills` уже создана — игнорируйте.

## Конфигурация

### Изменения не применились

OpenCode следит за конфигом и перезагружает MCP, навыки, агентов и плагины после сохранения. Форс: `/reload`. Перезапускать приложение не нужно.

### `$VAR` в конфиге не подставляется

В JSON-строках работает только `{env:NAME}`:

```jsonc
"environment": { "API_KEY": "{env:API_KEY}" }
```

### Конфликт `opencode.json` и `opencode.jsonc`

Оба файла обнаруживаются. Держите один; этот репозиторий ставит `opencode.jsonc`.

### Конфиг «не тот» после правки

Проверьте, какой файл выигрывает: проект `opencode.json(c)` перекрывает глобальный, `.opencode/` перекрывает прямой файл, системный `/etc/opencode` перекрывает всё.

## Деньги

- `web_research`, `parallel-deep-research`, Task API — платные, тарифицируются на аккаунт Parallel.
- `web_search`, `web_fetch`, `web_decisions`, `find_verticals` — бесплатны с лимитами.
- Локальные MCP (`memory`, `drawio`, `sequential-thinking`, `playwright`) не стоят ничего, кроме вашего CPU и токенов контекста.
